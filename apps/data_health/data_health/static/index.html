Is this data good enough to trust?

Sensor logs, test-bench exports and SCADA dumps carry problems that silently break analysis and machine learning: gaps, frozen sensors, error codes such as −999, a unit that changed after a firmware update, a flow meter that drifted. This tool reads the file, recognises the physical quantity and unit of each column, and checks it the way an experienced engineer would.

Every finding comes with the evidence (time spans, values) and a suggested fix, and the score explains how it was computed.

Optimize the process

Plain machine learning on your clean operating data: learn how the KPI depends on the levers you control and the conditions you don't, then recommend lever settings.

Example data: plant_operations_60d.csv

From data health to plant savings

Most plants already log what is needed to save energy: the setpoints operators choose, the weather, the load, and the consumption. The data shows which settings worked best in each situation. A gradient-boosting model learns that relation, and the optimizer recommends, for each hour, the lever settings with the best predicted KPI.

  1. Clean first. The health report removes error codes, frozen sensors, spikes and duplicate rows before training.
  2. Choose roles. The KPI to minimize or maximize (plant kW, specific energy, yield); the levers operators set (setpoints, speeds, valve positions); the context they don't (weather, load, feed); and constraints on other outputs (a return temperature, a pressure, a quality limit).
  3. Honest test. The model is scored on the most recent quarter of the record, which it never saw.
  4. Safe recommendations. Only settings similar to past operation, moved gradually, respecting every constraint with a margin.
  5. Actionable output. A setpoint schedule against the main driver (e.g. load), the expected saving with an uncertainty range, and which lever matters most.

No physics model is needed. The physics is used only to check the example: the plant is simulated, so the predicted saving can be compared with the true one.

Use it from code

The same analysis is a REST endpoint, so it can run in a data pipeline (nightly export check, CI for test-bench data, a gate before model training). Interactive documentation: /docs.
