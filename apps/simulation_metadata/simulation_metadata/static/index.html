Which settings produced this result, and did it converge?

Months later, nobody remembers which mesh, time step or turbulence model a result came from, or whether the run had actually converged. The answer is in the case files and the solver log, scattered across a dozen text formats. This service reads them and returns one structured record:

Solverapplication, version, steady / transient, physics, algorithm, run time
Meshcells, points, faces, patches, element types, bounding box, checkMesh quality
Time steppingΔt, end time, Courant limit, steps or increments actually run
Boundary conditionsevery field on every patch, loads and supports for FEA
Parametersviscosity, inlet velocity, materials, loads, an indicative Reynolds number
Convergencea verdict with its reasons and what to do next, plus the residual history

Use it to document a study, to index a simulation archive, or as the first step before training a surrogate model on simulation results, where every training sample must be traceable to converged runs.

Record schema (pinneapple.simmeta/1)

KeyContent
solvername, application, version, executed (date, host, processes, wall time)
analysissteady / transient (or FEA procedure), physics, turbulence model, algorithm, steps
meshcells / points / faces or nodes / elements, patches, element types, bounding box, quality
timestart, end, Δt, Courant limit, steps run, reached_end
boundary_conditionsfield, patch, type, value (OpenFOAM) or set, DOFs, value (FEA); loads for FEA
parameters / derivedphysical inputs with their source file; derived numbers with their definition
numericsschemes, linear solvers and tolerances, relaxation, residual targets
convergencestatus (converged, still_falling, stalled, diverged, crashed, completed, failed, incomplete), reasons, recommendations, per-field residuals, history
filesevery uploaded file with size, hash and whether it was used
